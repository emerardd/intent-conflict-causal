# Stage 3：把“授权判断”与输出字母拆开

日期：2026-08-28。执行者：本地 AI 编程代理。
这是已有项目的后续研究，不是重新计时的独立 16 小时申请任务。

**核心结果：授权相关信息可以跨输出映射、跨场景线性读出，但沿选出的
一维方向干预没有可靠改变决策。** 正式任务 288/288 首选输出正确；主站点
同措辞留出 AUROC 1.00、新措辞 0.898；480 次冻结干预 0 次首选输出翻转，
主效应 95% CI 跨零。应保留“可读出”结论，不能升级为“已识别因果控制机制”。

## 1. 这次到底要补什么证据

Stage 2 的任务固定“授权→执行→A，未授权→阻止→B”。所以其中的高
AUROC 和整条 residual state 替换，不能区分授权关系、执行/阻止决策、
输出字母计划或这些内容的混合。尤其不能由整条状态替换推出“找到了
一条特异性的授权方向”，更不能推出模型知道自己正在违反真实用户意图。

本轮先实现授权 × 指定控制器规则 × 输出映射的三因子版本 v1；小样本
行为门槛失败后，保留全部失败证据，只允许一次明确缩小问题的 v2：

> 模型尚未读到答案字母映射时，能否读出一个跨场景泛化的授权相关方向？
> 沿它做一维干预时，影响能否跟随字母映射、而不是始终偏向同一个字母？

v2 不再分离授权与规范性的“应执行/应阻止”。因此它最多补上
**输出字母混淆控制及方向级因果检验**，不是完整解决原来的意识/违规问题。

|---|---|---|

| 行为先验检查 | 全词表 argmax、A/B 概率质量、实际贪心生成 | v1 32 条；v2 16 条 pilot |

| 表征检验 | 仅训练集拟合方向；仅验证集选层；测试不能反过来选层 | 21 个位置×层站点全部保留；主位置选中第 16 层 |
| 低维干预 | 固定 ±0.5、±1、±2 训练间距；同轴正负方向；两个随机正交轴 | 完成 480 次 forward，未通过效应门槛 |
| 审计交付 | 独立正确率/AUROC/置信区间复算、测试、报告、hash 清单 | 独立复算与原分析精确复算均通过 |

没有启动。v2 是看过 v1 后的新版本，不能声称它在所有选择之前就已注册。

## 3. 三因子 v1 为什么停止

同一候选命令配两条记录：一条许可、一条禁止。授权条件只交换它们与
候选/干扰命令的绑定。NORMAL 控制器按授权执行；REVERSED 控制器反过来
执行。最后另给 A/B 字母图例。这里只是虚构无害命令的模拟，不执行真工具。

两个 pilot 场景 × 两种记录顺序 × 两种授权 × 两种规则 × 两种映射 = 32 条。

| 控制器规则 | 输出映射 | 正确数 | 观察到的字母 |
|---|---|---:|---|
| NORMAL | A=执行，B=阻止 | 8/8 | A:4，B:4 |
| NORMAL | A=阻止，B=执行 | 4/8 | 全部 B |
| REVERSED | A=执行，B=阻止 | 4/8 | 全部 B |
| REVERSED | A=阻止，B=执行 | 4/8 | 全部 B |

总正确率 **20/32=62.5%**。其余三个非标准条件的 24 条全部生成 B。
所有实际生成与全词表 argmax 一致，也都符合单字母格式；这不是仅比较
A/B logits 造成的虚假行为成功。

规定每个规则×映射 cell 至少 90% 正确，故 v1 失败并停止。由于 B 在不同
映射下对应不同动作，不能把这个现象直接称为“全拒绝”。也不能由 v1
失败推出 Stage 2 的方向一定只编码字母。更合理的结论是：这个三因子提示
在该模型/精度/小样本上不足以支撑预定的机制辨识。

v2 同时删除反转控制器并简化了系统/用户指令，所以 v2 变好也不是一个
隔离单一提示组件的因果实验；不能确定 v1 究竟被哪个组件破坏。

## 4. v2 任务是什么：用四格看清楚

| 候选动作授权状态 | 字母图例 | 规范动作 | 正确输出 |
|---|---|---|---|
| 已授权 | A=执行，B=阻止 | 执行 | A |
| 未授权 | A=执行，B=阻止 | 阻止 | B |
| 已授权 | A=阻止，B=执行 | 执行 | B |
| 未授权 | A=阻止，B=执行 | 阻止 | A |

如果某条方向只是在“想输出 B”，换图例后就不应继续稳定对应“未授权”。
如果沿方向干预后的字母偏好能随图例翻转，才有理由反对最简单的固定
字母偏置解释。不过“未授权”仍然和“应该阻止”完全一致，尚未拆开。

使用两个与 v1 不同的 pilot 场景；16 条全部正确，两种映射各 8/8，实际
贪心生成 16/16 正确。之后才打开此前没有见过模型响应的正式场景。

## 5. 模型、数据、位置和指标

- 模型：`Qwen/Qwen3.5-4B`，本地缓存 revision
  `851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a`；NF4 权重，bfloat16 计算；
  RTX 5060 Laptop 8 GB；不训练基础模型。
- 原生 chat template，关闭 thinking，不强制把解码空间限制成 A/B。
- 24 个新场景，8 个训练、4 个验证、12 个测试。每场景候选/干扰代码唯一。
  两种许可记录顺序配平。训练、验证、测试共享一种措辞；另一种措辞只用于测试。
- v2 正式样本：训练 64、验证 32、同措辞测试 96、新措辞测试 96，共 288。
  这不是 288 个独立场景：测试不确定性按 12 个场景聚类。
- 记录 decoder block 的输出，层索引 `[4,8,12,16,20,24,28]`（代码的
  零基索引）；测量记录结束、图例前、答案前三个位置。排除最后一层，避免
  最终归一化位置定义混淆。`pre_policy` 在 v2 仅是保留的内部名称。
- 行为：全词表首选 token 是否为正确字母；另存 A/B 内部选择、A+B 概率质量、
  格式是否正确。所有 pilot 都实际生成，正式集预先固定抽取每个 split 的第一个
  场景，共 32 条实际生成；其余 256 条仅测量 forward argmax。
- 方向：训练集“未授权均值−授权均值”，必要时去除训练集答案字母均值差方向，
  再单位化。不训练模型权重；这是基于固定激活估计线性方向。
- 选层：主位置固定 `pre_mapping`，最大化验证集两种映射分组和双向跨映射
  AUROC 的最小值；同分选最早层。AUROC 不事后取 `max(AUC,1-AUC)`。
- 因果：修改单个位置的 residual 向量 `h' = h ± αs d`，其中单位方向 `d`
  和间距 `s` 只来自训练集。不是把另一个例子的整条隐藏状态搬过来。

## 6. 正式行为与表征结果

| 数据分组 | 正常映射正确数 | 反转映射正确数 |
|---|---:|---:|
| 训练，同措辞 | 32/32 | 32/32 |
| 验证，同措辞 | 16/16 | 16/16 |
| 测试，同措辞 | 48/48 | 48/48 |
| 测试，未训练措辞 | 48/48 | 48/48 |

全词表 argmax **288/288** 正确；正式集实际生成抽查 **32/32** 正确，并与
forward 首 token 全部一致。这不等于 288 条都做了完整生成，更不等于执行
了 288 次真实工具动作。

验证选中 **图例前、layer index 16**：

| 指标 | 正常映射 | 反转映射 |
|---|---:|---:|
| 验证 AUROC | 1.000 | 1.000 |
| 同措辞留出测试 AUROC | 1.000 | 1.000 |
| 未训练措辞留出测试 AUROC | 0.897569 | 0.897569 |

在一种映射上拟合、另一种上测试得到相同值。测试场景的投影均值差：
同措辞 **0.5761**，场景 bootstrap 95% CI **[0.5531,0.6004]**；新措辞
**0.2478**，CI **[0.2219,0.2719]**。两组均为 12/12 场景方向一致，单侧
符号检验各 `p=1/4096`。这是方向一致性检验，不是“授权语义纯度”的 p 值。

重要防误读：在图例前，相同授权条件的两种映射拥有完全相同的 token 前缀，
本次数值激活也完全相同。因此答案字母均值差为零，`nuisance_rank=0`；
代码名虽为 `auth_clean`，实际没有去掉任何非零字母方向。前缀的映射不变性
本身由输入顺序保证，不能包装成模型涌现的发现。留出场景/措辞的授权可读性、
以及后续跨映射干预才是增量证据。

次要检验：原 Stage 2 NF4 第 16 层训练方向，在新测试集上的 AUROC：
记录结束 0.7257、图例前 0.8542、答案前 1.0000，两种映射都相同。
这不支持“旧方向只能读出字面 B”的最简单解释，但未分离规范性动作语义，
也没有直接干预旧方向，不能把这个 transfer 叫作旧机制的因果复现。

## 7. 因果干预结果

使用 12 个测试场景 × 两种授权 × 两种映射 = 48 个接收样本，固定同措辞、
候选记录在前。训练集间距 `s=0.6105854692`，干预 `h±αsd`。
主方向三个强度各 ± 两次，共 288 次 forward；两个随机正交轴各 ±1，
共 192 次，总计 **480 次**。图例前字母方向为零，依预注册不构造虚假的
单位字母方向对照；v2 没有动作方向对照，因为动作与授权重合。

主统计量是 `0.5 × [margin(+α)−margin(−α)]`，其中
`margin=log p(B)−log p(A)`，再按图例乘正/负号，使正值统一表示朝“更像
未授权/更应阻止”的方向变化。每场景先平均四个接收样本，再对 12 个场景
做 5000 次 bootstrap。它的单位是对数概率差，不是准确率百分点。

| 方向与强度 | 平均对齐效应 | 场景级 95% CI | 首选输出翻转 |
|---|---:|---|---:|
| 授权相关方向，α=0.5 | −0.007813 | [−0.018229, 0.002604] | 0/96 |
| **授权相关方向，α=1（主检验）** | **−0.006510** | **[−0.019531, 0.006510]** | **0/96** |
| 授权相关方向，α=2 | 0.001302 | [−0.010417, 0.011719] | 0/96 |
| 随机轴 0，α=1 | −0.005208 | [−0.014323, 0.002604] | 0/96 |
| 随机轴 1，α=1 | 0.001302 | [−0.010417, 0.010417] | 0/96 |

主检验两种映射的均值分别为 −0.0078125、−0.0052083；没有要求的双正向。
主方向减随机轴 0 的 CI 为 [−0.019531,0.015625]，减随机轴 1 的 CI 为
[−0.027344,0.015625]，均跨零。所有干预都保持 A/B 首 token 格式，但均不
翻转原先正确的选择。第一个测试场景的 ±1 实际单 token 生成共 8 次，全部
与对应干预 forward 一致。首个 null patch 重现 baseline。

负结果之后另做了明确标为事后的四次实现诊断：固定第一个接收样本，重跑
baseline、null、原来的 ±1，并在 patch 之后读取实际写入的向量。请求扰动
范数为 0.610585，实际正/负扰动范数约 0.6123，方向投影符号正确；baseline
向量范数为 10.6108。四个结果都精确重现对应存档。因此干预确实写入、没有
因 dtype 转换变成零；但这不是“已知能改变行为”的正对照。记录发现输出
logits 也是 bfloat16，进一步提示不应对很小的差值过度解释。

所以冻结的 `conditional_rule_consistent_effect=false`。没有为了得到正结果
事后改用 layer 20/24、答案位置、更强扰动或筛选某个有利场景。

**能下的结论：**在这个模型/精度、图例前第 16 层、这条均值差方向和这些
强度下，没有找到可靠的、随映射一致变化的因果效应。

**不能下的结论：**模型没有授权信息；所有授权表征都无因果作用；授权只是
输出字母；或模型不知道自己违规。另一些位置、多个 token、别的子空间可能
参与计算，当前任务也可能有冗余路径。单 token 的 marker 位置可被读出，
但未必是下游实际读取的关键位置。本轮没有同位置、已知足以改变行为的
正对照，也没有高精度复现，因此不能把全部近零差异确认为数值噪声。

## 8. 下一轮值得做的最小问题（尚未执行）

不要立即扩展成“知道自己在违规”。先回答一个可判别的问题：

> 图例前 marker 上的授权信息是下游真正读取的中间量，还是一个可读但没有
> 显著因果影响的旁支表示？

下一轮只应固定少数位置、预先规定对照，比较“同位置整状态替换”与“当前
一维方向”，再考虑候选命令末 token 等内容位置。若整状态能影响而一维
不能，优先考察子空间/分布式表示；若同位置整状态也不起作用而内容位置
起作用，优先考察信息实际被读取的位置。若连明确的行为正对照都失败，先
审计干预装置与精度，不继续解释语义。这是未来方案，不计入本轮已完成证据。

还应预先安排一次 BF16 的小范围精度对照、匹配的自然激活投影尺度，并为
新的选择保留新场景。只有获得稳定的映射一致因果效应后，才值得进一步
拆开授权和实际行动，最后迁移到真正的 injection/未授权执行。

## 9. 实现检查与限制

1. 最初一次 tokenizer 预检因 Transformers 返回 `BatchEncoding` 而中止，
   尚未执行任何模型 forward。核实两个路径实际 token IDs 相同后，改用既有
   归一化 helper 并增加回归测试；提示和阈值不变。失败快照保留。
2. v1 同前缀、不同总长度的激活出现小差异。额外四次 forward 的事后诊断中，
   同长度换后缀和只跑前缀均完全相同；214 vs 216 tokens 最大差 0.0625，
   相对 L2 差 0.0131。这支持长度相关的数值/实现敏感性，不证明未来内容泄漏。
   v2 pilot 和正式集的两种映射在两个前置位置的差异都恰为零。
3. 独立审计脚本使用算术真值表、成对排序 AUROC 和另一套统计实现，检查原始
   输出、全部 21 个站点、选层、方向和场景级不确定性；不调用原分析函数。
   这不是第二名人类研究者或独立模型复跑，AI 写两套代码仍可能共享概念错误。
4. 所有干预只针对同措辞、候选记录在前的 12 个测试场景，没有验证另一个
   顺序、新措辞上的因果效应。两个随机轴不足以证明语义特异性。
5. v2 不分离授权与“应阻止”，更不包含自然未授权执行、真实注入攻击、
   自发违规、自我报告或真实工具结果。“知道自己在违规”仍未被测量。
6. 单个 4B 模型、NF4 精度、单 seed、手工合成任务；没有跨精度、跨模型的
   Stage 3 复现。不要拿 Stage 2 的跨模型结果代替这一设计的复现。
7. 依赖仍复用相邻项目的环境；完整包清单不是便携锁文件。当前程序记录模型
   revision，但配置没有硬钉 revision；全新环境复跑未验证。CPU 审计路径不依赖
   GPU 或 Stage 2 激活档案，详见 `stage3-reproduction.md`。

最终验证：30 项测试通过，原分析精确复算通过，独立统计复算通过；
`git diff --check` 通过。原始/当前源码 hash 分开保存，确保事后审计脚本
和报告不会被误认为推理之前已经冻结的代码。
